## This session: T008 — `cli.py`

**Goal:** make `python -m elvideo index in.mp4` work end to end. One command, one file, no UI.
This is the first line of the Definition of Done.

**Acceptance criteria** (restated in full — `tasks/T008-cli.md` is authoritative if they disagree):

- [ ] `uv run python -m elvideo index in.mp4` produces a valid `work/footage_index.json`.
- [ ] `--fps` overrides the sampling rate **for that run only** — the per-video knob, surfaced
      where a user can actually reach it.
- [ ] `--media-resolution` accepts only `low` / `medium` / `high`, rejecting anything else with a
      usable message rather than passing it through to the API.
- [ ] `--work-dir` is respected, and the directory (plus `keyframes/`) is created if absent.
- [ ] Per-stage timing is printed in human-readable form via `rich`.
- [ ] Exit code is **non-zero** on: missing video file, missing `GEMINI_API_KEY`, schema validation
      failure. Silent success on a broken run is the worst outcome here.
- [ ] Error messages name the fix, not just the fault — "GEMINI_API_KEY not set; copy .env.example
      to .env" beats a stack trace.
- [ ] `--help` explains the `--fps` knob well enough that someone picks the right value for
      talking-head vs action footage without reading the spec.
- [ ] `.env` is loaded via `python-dotenv` at startup.

**What `build_index` already gives you** — do not reimplement any of it:

```python
build_index(path, work_dir="work", fps=0.5, media_resolution="low", *, threshold=27.0)
    -> dict[str, Any]
```

It logs one line per stage plus a total, validates before writing, and writes
`{work_dir}/footage_index.json` itself. It raises `FileNotFoundError` (missing video),
`RuntimeError` (wrong Gemini call count, or an unset/blank `GEMINI_API_KEY` from `gemini.py`),
`ValueError` (out-of-range `shot_index`) and `jsonschema.ValidationError` (contract violation) —
that list is your exit-code mapping.

**`--threshold` is worth surfacing too** (D-012 calls the detector threshold a per-video knob, and
`build_index` already accepts it keyword-only), but it is not in the criteria — decide, and say so
either way rather than leaving it silently unexposed.

## Constraints that bite on this task specifically

- **Two traps already hit and fixed at bootstrap. Do not reintroduce them.**
  1. Typer **collapses a single-command app**, dropping the subcommand name — `python -m elvideo
     index in.mp4` then parses as an unexpected extra argument. An `@app.callback()` forces
     multi-command mode. It is already there; leave it.
  2. **Help strings must be ASCII-only.** The Windows console is cp1252 and a `≤` in the app help
     crashed `--help` with `UnicodeEncodeError`. Docstrings and markdown are fine — anything Typer
     *prints* is not.
- **Keep the module thin.** If logic starts accumulating here it is in the wrong file: `build_index`
  has to be reusable without inheriting our argument parsing.
- **No UI, no upload form, no batch mode, no concurrent jobs** (`docs/IDEA.md` § *Non-goals*). One
  file per invocation.
- **`elvideo/__main__.py` already exists** to make `python -m elvideo` resolve (D-006).
- **The model string is pinned** (`gemini-3.5-flash`) and is not a CLI option.
